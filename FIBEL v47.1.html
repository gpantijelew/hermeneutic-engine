Dezember 2025 **Autoren:** Grigori (Vision) + Claude Sonnet 4.5 (Architektur) + Gemini 3 (Implementierung) **Status:** Production (with v48-Preview-Features) --- ## 🎯 MISSION STATEMENT Das Forschungs-Cockpit ist ein **hermeneutisches RAG-System** für die qualitative Analyse von AI-Diskursen. Es ermöglicht die **Langzeit-Beobachtung** von KI-Modellen (GPT, Claude, Gemini, DeepSeek, Kimi, etc.) durch **semantische Suche + zitierende Synthese**. **Kern-Innovation:** Nicht "Was hat ein Modell gesagt?", sondern **"Wie entwickelt sich ein Modell über Zeit? Wo konvergieren/divergieren verschiedene KIs?"** --- ## 🏗️ ARCHITEKTUR-PRINZIPIEN ### 1. **Hermeneutik vor Retrieval** **Traditionelles RAG:** - Hole Top-K Chunks - Gib Chunks an LLM - LLM fasst zusammen **Hermeneutic Engine:** - Hole Top-K Chunks - **Rerank hermeneutisch** (LLM-as-Judge: "Beantwortet dieser Chunk die Frage WIRKLICH?") - Sortiere chronologisch + nach Speaker - **Synthese mit Tiefenanalyse** (Temporal Development + Cross-Model-Comparison) - **Enforcer validiert Zitate** (prüft, ob Synthese korrekt ist) **Resultat:** Nicht Zusammenfassung, sondern **Interpretation**. --- ### 2. **Zitation als Fundament** **Problem klassischer RAG-Systeme:** - LLM halluziniert Fakten - Nutzer kann Quellen nicht prüfen **Lösung:** - **Jede Aussage wird zitiert** (Format: `[1]`, `[2]`, etc.) - **Enforcer prüft Zitate** (Struktur-Check: Sind alle Zitate valide?) - **Deep-Check optional** (Faktencheck: Sagt die Quelle wirklich das, was behauptet wird?) **Ziel:** Transparenz + Verifizierbarkeit (wie in wissenschaftlichen Papers) --- ### 3. **Chronologie + Speaker-Blocks** **Key Insight:** AI-Modelle entwickeln sich über Zeit. Ein Claude-Chat von 2023 ist NICHT derselbe wie 2025. **Implementierung:** ```markdown ### CLAUDE (v3.5, 2024-01-15) [Chunks chronologisch sortiert] ### CLAUDE (v3.5, 2024-06-20) [Chunks chronologisch sortiert] ### DEEPSEEK (v2, 2024-08-10) [Chunks chronologisch sortiert] ``` **Synthese-Prompt zwingt zu:** - **Pro-Modell-Chronologie:** Wie entwickelt sich Claude von Jan → Jun? - **Cross-Modell-Vergleich:** Wie unterscheidet sich Claude von DeepSeek? **Resultat:** Längsschnitt-Analyse + Querschnitt-Vergleich --- ### 4. **Adaptive Search Intelligence** **Problem:** Eine Query wie "DeepSeek" (Eigenname) braucht **Präzision** (Keyword-Matching). Eine Query wie "Was ist Zensur?" braucht **Konzept-Suche** (Semantik). **Lösung: Adaptive Keyword-Gewichtung** ```python # 1. Extract Keywords keywords = ["DeepSeek", "Zensur", "Modell"] # 2. Detect Query Type has_proper_nouns = "DeepSeek" in query if has_proper_nouns: keyword_weight = 0.60 # Präzisions-Modus else: keyword_weight = 0.20 # Konzept-Modus # 3. Hybrid Search results = vector_store.hybrid_search( query, keywords, keyword_weight=keyword_weight ) ``` **Resultat:** System passt sich automatisch an Query-Typ an. --- ## 🧩 KOMPONENTEN-ÜBERSICHT ### **1. Vector Store (`FirestoreVectorStore`)** **Aufgabe:** Speichern + Suchen von Embeddings **Features:** - Hybrid Search (Vektor + Keywords) - Adaptive Keyword-Gewichtung - Scope-Filter (Investigativ-Modus: nur ausgewählte Chats) - Role-Filter (nur User, nur Model) **Technologie:** Firestore + text-embedding-004 --- ### **2. Post-Processing (Cleanup, Formatierung) ``` **v48-Feature: Exegese vs. Diskurs** System erkennt automatisch Query-Typ: - **EXEGESE-Modus** (für "Was ist X?", "Erkläre Y"): - Fokus: Definition, Erklärung, Kontext - Prompt: "Analysiere die Bedeutung und den Kontext" - **DISKURS-Modus** (für "Vergleiche X und Y", "Wie unterscheidet sich..."): - Fokus: Vergleich, Debatte, Konvergenz/Divergenz - Prompt: "Analysiere Gemeinsamkeiten und Unterschiede" **Return-Value:** ```python raw_answer, used_sources, mode_name = rag_engine.generate_answer(query, results) # mode_name: "exegesis" oder "discourse" ``` **Key-Feature:** Thought/Speech-Splitting AI-Antworten haben oft interne Gedanken (``) + externe Aussagen. (`[1]`, `[2]`, etc.) - Gibt es Zitate außerhalb des Bereichs? System holt relevante Fakten, bevor es antwortet. **Hermeneutik:** Kunst der Interpretation. Nicht "Was steht da?", sondern "Was bedeutet das?" **Enforcer:** Validierungs-Layer. Prüft, ob Synthese korrekt zitiert. **Speaker-Blocks:** Strukturierung der Synthese nach Sprecher (z.B. Claude, DeepSeek) + Chronologie. **Exegese:** Erklärung + Interpretation (z.B. "Was ist X?") **Diskurs:** Vergleich + Debatte (z.B. "Wie unterscheidet sich X von Y?") **Investigativ-Modus:** Scope-Filter: Nur ausgewählte Chats durchsuchen (reduziert Noise). **Gedächtnis-Modus:** Scope-Filter: Alle Chats durchsuchen (maximale Abdeckung). **Context Poisoning:** LLM "klebt" an fehlerhaftem Zustand im Context Window → Reparatur-Versuche machen es schlimmer. **Surgical Edit:** "Nur das Gefragte ändern" (nicht Refactoring, nicht "Aufräumen"). **SAKROSANKT:** Heilig, unantastbar. Darf nur nach expliziter Genehmigung geändert werden (z.B. Sidebar-Struktur). --- ## 🎯 QUICK REFERENCE ### **Typische User-Workflows** **1.
